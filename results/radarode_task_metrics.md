# radarODE-MTL の波形再構成・R 波位置の評価(2026-10-02)

目的: 我々ルール(被験者分割 11 分割・200 エポック)の学習で、PPI 以外の 2 タスクも論文 Table I の等重み行と並べる。
スクリプト `scripts/radarode_task_eval.py <run> [--stride 40] [--thr 0.5] [--ckpt auto|last]`(launch_wsst.sh と同じ環境変数)。

|---|---|---|

## 読み方

1. **波形の PCC・R² は、入力を見ない対照(平均の片)と差がない。** 我々の片は「窓中央をまたぐ R–R を 200 点に補間」で形がそろうため、
   PCC 93 % は手法の良さを表さない。論文の 79.7 % は片の切り方が違う(著者のデータ生成は `ecg_seg_index_<obj>.csv` の境界で切るが、その csv は公開されていない)。
   並べるときは対照の値を必ず併記する。
2. **アンカーの時間誤差 35 ms は、公開実装のデコーダの性質。** 公開実装 `nets/anchor_decoder.py` の冒頭に
   「another design of the anchor_decoder, which is different from the one in paper」とある。論文の 9.7 ms を出したデコーダは公開されていない。
   - 符号つき誤差(予測 − 正解)は中央値 −25 ms(ep17)、−35 ms(ep199)。正解の R 波のまわりの平均出力は幅 ±60 ms の広い山で、頂点が −25 ms。
     損失が 1 点のスパイク(0/1)に対する MSE なので、広く低い山が最適解になる(出力の最大値の中央値 0.056)。
   - ep17 では窓内の位置で誤差が直線的に変わる(先頭 0〜0.5 s で −35〜−40 ms、末尾 3.5〜4 s で −10 ms、窓全体で 38 ms)。
     デコーダは 31 フレーム → 811 点 → 800 点に切り詰める構造で、全重み 1 で測った時間格子は 1 フレームあたり 26.0 点(真は 800/31 = 25.8 点)。
     0.9 % の伸びは窓全体で 7 点 = 36 ms に相当し、観測した 38 ms と合う。畳み込みは位置に依る補正を学べないので残る。
3. MDR はしきい値で何倍も変わる(0.3 で 1.3 %、0.5 で 3.8 %、0.7 で 14 %)。0.5 は教師 0/1 の中点として test を見る前に決めた値。
4. RMSE の単位: 公開実装の損失は片ごとに [0,1] に正規化するので「mV」は文字どおりではない可能性。[0,1] 尺度と ECG の単位の両方を出す。

## 我々ルール(LOSO 11 分割)での手順

学習器(repro/trainer.py 2026-10-02)が `best_ECG_shape.pt` / `best_Anchor.pt` と `best_<task>_epoch.json` を残す。
LOSO 完了後に各分割で `--ckpt auto` を回し、保存したエポックと履歴上の最小エポックを併記する(途中から再起動した分割は、それ以前の最良を取り戻せない)。
